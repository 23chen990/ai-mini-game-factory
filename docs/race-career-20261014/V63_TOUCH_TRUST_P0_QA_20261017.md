# 极速飞驰 V6.3｜P0 手机触控可信度修复 / 对外试玩阻断

## 本次改动的严格范围
前提：真实玩家反映移动端“不灵敏，玩不下去”，桌面好玩。此前虽然 V6.2 Node/Chromium 浏览器验收通过，但没有真人真机手感通过的证据。

**实际修复：**
- 单一浮动轮盘继续保留，但消除**可见轮盘与真实输入语义不一致**：按可见圆环左右两侧（中心偏移 >= 34% 半径，且 <= 105% 半径）直接转向；按中央摇杆、或圆环外松散区域仍从中立开始滑动。移动过程中仍可连续模拟转向、自动移动虚拟中心并反打。不恢复旧的左/右双按钮，也不自动过弯。
- 修复某些触摸浏览器的 `setPointerCapture` 失败：降级为监听 window 的相同 pointerId 移动；window 上的 `pointerup/pointercancel` 是安全兜底，不泄露其他手指控制。暂停、失焦和返回大厅照常清除输入。
- 原有短按漂移、小喷缓冲、手动氮气、道具输入、车辆偏航、漂移惯性、近道和 30 关全部不改变。
- 添加**本机内存中的性能摘要**：触摸事件数、反打数、触摸到原生输入取样的 p95、overlay RAF 帧耗时 p95、超过 50ms 的帧数。最大只保留最近 120 次取样，不记录手指坐标、标识符；仅玩家点击已有“导出数据”才写入下载文件。它们**不是**真实触摸到屏幕像素/相机运动的端到端延迟，禁止冒充这一指标。

## 自动化应验收的 8 个动作
1. 手机横屏轮盘：触碰可见左外圈 **无需先移动** 就立即产生左转；右外圈同理；点击中间仍中立（有真实 2D PointerEvent/原生 g.input 的检查）。
2. 单指从左到右反打，原生 PlayerCar.steer 必须改变符号。
3. 同时第二指按漂移，第一指的 steering 不能卡住；快捷小喷和氮气保持原来的一次性消费规则。
4. 按住右侧按钮时左手继续转向，点击外侧和多指都不能抢占轮盘 pointerId。
5. 对 PointerCapture 抛错做退化：只认原来的 pointerId；同一手指可以跨轮盘区域移动；窗口级 pointerup/cancel 必须松手。
6. 暂停、失焦、横竖屏中断、结束后轴值归零；不能留下幻影漂移或氮气。
7. 触摸事件计时数据和帧耗时只在本机存在，最多 120 个样本，不能打印可识别手指坐标或自动上报。
8. 各种横屏尺寸触控区不能相互遮挡；本次不缩短已有右手按键间距，也不改速度/关卡目标。

## 真机发布前的 P0 闸门（NOT_RUN）
- iPhone Safari 和 Android Chrome 各连续 3 局：采用同一阶段真实路线，近端左/右轻按、中央按住拖动、急弯左右反打、漂移加小喷、松手回正；再对比桌面键盘。
- 记录机型、系统、浏览器、源码 SHA、每局主观是否能控制车、关键操作失败频次；有条件时导出**授权**的本地试玩摘要。
- 一旦再次出现玩家“无法控制、不灵敏、玩不下去”，这次自动化通过也不意味着可以发布。重点测真实触屏输入→渲染画面而不是改赛道难度。
- **不根据最高车速沿中心线的曲率估算降低关卡难度**。正常漂移、走线、入弯时机是竞技技术，不是 bug。
