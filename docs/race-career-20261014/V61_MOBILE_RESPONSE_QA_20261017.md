# 极速飞驰 V6.1｜手机操控响应与帧率体验验收（2026-10-17）

## 背景与边界
真人反馈：同一游戏手机比电脑手感差，方向回正、漂移反打有迟滞感。基于 V6.0（30 条赛道）独立 Draft PR 修复手机输入响应和渲染；**不恢复双键、不改 AI 难度、不改关卡目标、不开正式广告**。

当前修改：
- 左侧固定方向轮盘：低幅输入死区 7.5%，全量程约 66% 半径，较旧版更快达到有效转向。右手保留漂移、小喷、氮气、道具。
- 手机模拟方向输入使用更快的原生阻尼，降低高速时转向衰减；键盘保留原数值。
- 手机跟随镜头提高朝向追踪速度，车身实际运动仍由原生物理积分、漂移状态、护栏和速度决定。
- 持续低帧率启动画质逐级降低；用户明确手选画质不静默覆盖。
- `window.__RACE_EVIDENCE__` 提供本地只读 `fpsEstimate`、`touchToInputSampleMs` 和 `steerAxis`，不自动上传、不代表触摸到最终可见像素的真实端到端延迟。

## 真实手机测试（每种浏览器/手机至少 3 局）
1. 横屏比赛。先用「流畅」画质完成 01、05、11 关，再在同手机、同关改用「均衡」重复。区分画质卡顿与方向输入迟滞。
2. 直线小幅左→中→右，观察轮盘、赛车轮、车身轨迹和摄像机是否同步；不靠屏幕上提示文案引导操作。
3. 以玩家真实速度入连续 S 弯，按住漂移并向反方向反打，松手回正；重点记录转向正确但车身继续偏航的情况。
4. 左拇指持续转向时右拇指连续按漂移、小喷、氮气，验证没有丢键/错误连发；横屏手势中断后不得继续保持方向。
5. 连续玩 3 局，观察发热、掉帧、切后台恢复、道具命中旋转状态；区分物理失控与实际输入丢失。

记录设备/系统/浏览器、关卡、构建 `SOURCE_COMMIT`、约 15 秒问题录像、体感时点、实际表现。有条件的情况下，可用远程调试抓 `__RACE_EVIDENCE__`，这只是输入采样/帧率近似，不是照片或端到端屏幕延迟的证明。

## 判定
- 不出现原生游戏没收到方向、松手后仍保持漂移键、双指失焦造成卡方向。
- 同样操作下，手机版反打与键盘的轨迹规律一致，物理惯性可预测，但不要求手机车辆瞬间消除侧滑。
- 低/均衡画质的控制响应没有明显的 30–45FPS 持续卡顿；若有，先做真机性能分析再选择降画质/减特效。
- 完赛统计、失败原因、燃油、广告授权、30 关实体路线和 AI 对手不得被自动测试或性能修复偷偷篡改。

仅 Chrome/Playwright CI 通过 **不是** 真机通过；未证实 QQ 飞车同等手感，不得宣传。

## V6.1 后续：手机界面刷新预算（性能优化，不改比赛）

- 比赛输入采样、原生赛车 120Hz 固定步进、AI、挑战完成/淘汰判定和质量监控仍按原先每帧更新。
- 仅把 HUD 的速度数字、动态目标进度、淘汰条、物品图标、集气视觉状态等 DOM 更新限制为约 30Hz。手指按下/松开轮盘的视觉变换仍直接响应 PointerEvent，不经 HUD 节流。
- 性能验收：横屏同设备对比连续竞速和道具赛。观察轮盘是否仍直接跟手、氮气和小喷按键立刻生效，HUD 刷新频率不应被误解为转向采样频率。
