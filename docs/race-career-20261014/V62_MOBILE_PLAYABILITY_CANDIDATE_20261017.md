# 《极速飞驰》V6.2｜手机可玩性重构验收

**状态：代码候选，真机体验未通过验收。不能因为 CI 全绿就宣称适合正式发布。**

## 为什么要重构
真人手机测试明确反馈“不好玩、不灵敏、电脑上好玩多了，手机玩不下去”。因此之前的 V6.1 代码/浏览器通过只视为功能完整性证据，不能代表实际手感。

## 本次交付的实际变化
- 首次进入手机 H5 **优先使用低 GPU 开销**：不启用昂贵的 Bloom、动态阴影；移动设备禁用原生 WebGL MSAA；低画质按 1x DPR 渲染。用户可以在暂停时自行改画质；已明确选择的画质偏好仍有效。
- 即使玩家以前手选了「均衡」，手机均衡档也把 DPR 上限从 1.5x 调为 1.2x，并关闭移动端 Bloom 与动态阴影；桌面保持原渲染设置。
- 仅手机使用**自适应浮动轮盘**：触摸点作为初始中心，首次触碰无虚假方向；轻微拖动有更清晰的模拟方向反馈；滑到极端时浮动中心会跟随手指移动，缩短反打需要回拉的距离；转向仍由玩家左右手指实际位置决定，没有自动过弯。
- 扩大左下角轮盘的触控区，保持可见圆盘、右手漂移/小喷/氮气/道具四个独立按键。仍无旧双键切换。
- 继承 V6.1：漂移快速短按不漏输入、有效反打的渐进抓地力恢复、倒计时左拇指可预按、HUD 约 30Hz DOM 显示限频、不降低原生物理或 AI/关卡刷新频率。
- 本地只读调试 `window.__RACE_EVIDENCE__` 增加 renderPixelRatio、composerActive、shadowsActive、floatingWheel、wheelAnchorPx；并有 fpsEstimate、touchToInputSampleMs、nativeSteer、playerYaw 等，**不自动上传**。

## 通过/失败判据
1. **先核实构建**：仅使用 PR 对应的经 CI 验证的 `preview/racing-v61-mobile-response-20261017/index.html`。检查 `PREVIEW_PROVENANCE.txt` 的 SOURCE_COMMIT 必须等于实际测试提交；旧缓存、旧 SHA 不可当本版。
2. **真实手机 3 局**：至少一台 iPhone Safari 和一台 Android Chrome，各连续 3 局。检查横屏安全区、按键遮挡、手机是否过热，低画质下是否持续掉帧；记录具体机型、系统版本、浏览器与关卡。
3. **手指即刻跟随**：各做 20 次轻触→短移→松手、以及大幅拉过头→40–50px 反打。必须没有“轮盘跟手但赛车几秒后才响应”或“必须把手指重新拖回起点才能反打”。
4. **真实双指**：方向轮盘持续触摸时，另一个拇指漂移/小喷/氮气/道具各至少 10 次；接触取消、切后台、锁屏、暂停、切横竖屏后不能出现卡方向、幻影漂移或扣错资源。
5. **物理与操作分离**：在赛道速度足够时验证原生赛车确实按反向输入改变前轮角与车身偏航，允许正常滑行动力学惯性，但玩家应能够预测。游戏失败不得主要由输入丢失和帧率造成。
6. **可玩性门槛**：真人可以不被 UI 阻碍地玩满 3 局，并愿意再挑战；若多数玩家仍评价手机明显难以玩下去，**拒绝正式发布并继续重构，而不是假装完成**。

## 自动化测试范围与局限
- Node 测试：浮动起点中立、短行程小幅响应、过度拉动后反打、额外手指不抢控制、漂移短按及取消清理、手机质量分档与 GPU 渲染补丁。
- Chromium 软件 WebGL：用正确的两指 active contact set 发触摸、跟踪真实 native input / PlayerCar.steer、验证屏幕宽度/安全区/按钮及新手低成本渲染初始化、倒计时预触摸。
- 浏览器 CI 不是物理真机。不得编造真机 FPS、端到端触控毫秒、玩家意愿或广告展示数据。真机测试为发布前置条件。

## 暂不修改
30 个真实实体赛道、AI 难度、关卡目标、燃油收支、广告触发和存档。不会用自动驾驶/吸附赛道、免费奖励、自动小喷来掩盖操作问题。

## 极端卡顿与短屏补充
- 低画质默认已消除桌面模板遗留的 Bloom/动态阴影负担；手机「均衡」也不重新打开这些重型效果。
- 只有**持续严重掉帧**（例如连续约 13FPS）或重复超长帧时，手动选择的高画质也会临时降级到适合驾控的档位。不会重写玩家本地画质偏好，不会因单次切后台恢复而降级。
- 320–375px 横屏高度下，扩大后的轮盘可能顶到原来的速度信息区，因此短屏速度数值向轮盘右侧重新布局。浏览器测试应直接对比两个真实矩形，不允许两者遮挡。
