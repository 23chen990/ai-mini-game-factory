## 实际观察：布局是操作关系，不是装饰

| 核心关系 | 参考实际观察 | 当前候选实际观察 | 不能据此声称 |
| --- | --- | --- | --- |
| 起始目标与落点 | 同一支撑路径上的连续目标；离散点击/落地可产生连续切割 | 目标在不同高度及支撑物周边；慢速点击多次先撞到支撑面。改用短促抬升后释放，能切到后面的目标 | 不能说所有目标不可达；改变输入确实改善了结果 |
| 一组内的连续操作回报 | 多组竖向结构，由可独立切断的细条组成；一次局部穿行可留下多处切口和连续奖励 | 两组粗粒度的支撑配对、零散目标和一座三物体塔；本次中段穿行中，一个名为 `ladder-stack` 的对象表现为一次椰子切割事件，并非多条独立切割 | 不能只凭变量名“stack/ladder”算恢复了参考结构，也不能要求照抄造型/坐标 |
| 压力—恢复—再获益顺序 | 缺口会导致失败；延长飞行可到达下一支撑。经过成组切割后跨过尖刺，后面仍有食物可继续切 | 本次高路线先取得高处奖励，再飞向上方终点，未与大部分结构互动 | 不能说候选没有危险，也不能直接判定允许绕行是 bug |
| 结算能证明什么 | 核验录屏有物理终点和结算；本次新鲜会话末帧在终点下方，未记录成功结算/重玩 | 正常操作达到 ×4 结算，并点击可见重玩按钮回到准备状态；只切了 **6/24** 个运行时切割单元，三个塔对象均未切 | 结算/重玩成功不能证明成组切割与压力顺序被体验到；6/24 本身也不是参考规定的失败阈值 |

这些证据支持“目标组合、支撑面和运动路径的关系不同，导致连续切割机会不同”。它们不证明某一套布局必然不好玩、不证明所有关卡都有相同问题，也不证明参考必须切完每个目标。数值仅描述本次候选，不作为第三方平衡值复用。

## 为什么上一次漏掉重点

1. **观察粒度偏小**：检查“能不能切、能不能重玩、提示是否显示”，没有先问“什么布局让玩家连续切、何时必须改变操作、改变后得到什么”。
2. **协议替代了玩家意图**：固定间隔点击方便复现，却可能直接飞过目标组；通关和计数掩盖了未发生的核心互动。保留成功改换操作的反例，才能避免把控制不熟练误判为不可达。
3. **合同清单造成盲区**：本轮先用失败回归证明，原比较器只遍历合同中的 check，外部 QA 提交的额外观察可以被忽略，已知项全绿仍能通过。它不能解释全部历史问题，但确实是共享链路的一个缺口。
4. **研究结论没有持续跟踪**：`research-slice-core-20260930/synthesis/core-model.json` 已写出紧密目标行、缺口、竖向结构、尖刺和终点；`gap-matrix.json` 已将结构差距列为 high。实施合同只有较泛的空间目标/结构/关卡变化描述，没有对应的成组互动验收。

旧 gap 绑定的是 `435ed539…`，不是本次 `c4cc3c…`。重设计提案仍为 `AWAITING_USER_CONFIRMATION`，其他工作区还存在布局延期决定。因此**不能把旧差距直接判成当前 Builder 违反已批准要求**；应核对版本和延期范围。研究 JSON 未被运行时 import 本身不是错误，编译成原创关卡数据完全合理；缺的是从证据到当前行为及验收的可核对映射。

## 接入共享流程的最小改动

没有新增 Agent、Schema、生产阶段、依赖或服务。

- 在原 `game-playtest` 与 QA 交接中加入：先看参考核心片段；优先检查分组/间距与运动可达性、连续回报、压力恢复顺序；按玩家意图对照；复用旧研究并核对旧 gap/延期的版本。
- 复用已有 capture `observations`：关键的合同外参考观察不能被静默丢弃，进入 `CONTRACT → REFERENCE_DEEP_RESEARCH`；只有候选观察、没有参考依据的，进入 `QA` 补证据。
- 该路由是**核对合同的待办**，不是自动批准新游戏需求，更不是让 Fixer 立即重做关卡。没有实测值就保留缺口，不编造指标；不以更改艺术风格或布局本身作为失败理由。
- 先运行红测，再实施修改；lint、typecheck、184 文件/1131 项工厂测试通过。新增测试为合成路由回归，**不是实际游戏体验通过证据**。

成本理由：避免 QA 已看到核心差异却因合同漏项而假通过，避免把研究/需求缺口错误交给 Fixer 反复改游戏；复用已核验研究，少做重复调查。新增成本是已有 QA 的定向观察与本地路由判断。**尚无节省工期、模型费用或人工次数的对照数据。**
