# UI 动画连续性规范（v1）

本规范用于所有后续生成游戏的 HUD、菜单、弹层、图标、数值反馈和状态切换。核心原则是：
**AI 负责少量稳定关键姿势，运行时负责连续运动**。不要把一组彼此独立生成的 AI 图片直接当作等时长帧播放。

Builder 收到的输入中包含经 `UiAnimationStandardSchema` 校验的 `uiAnimationStandard`。它是实现约束，
不是可自由改写的美术建议。

## 为什么逐帧 AI 图会“卡”

常见问题不只是帧数少，而是四种误差叠加：

1. **语义漂移**：人物五官、轮廓、衣服细节、图标形状在相邻帧中发生跳变。
2. **空间漂移**：每张图的画布、裁切框、相机、缩放或锚点不同，播放时主体会抖动。
3. **时间错误**：一张图绑定一个渲染帧；30/60/120 Hz 设备上的速度不同，掉帧时动作也变慢。
4. **运行时卡顿**：播放过程中修改图片 URL、临时解码或上传纹理，造成真正的掉帧。

增加更多独立生成帧通常会放大前两项，并不能根治问题。

## 动画形式选择

| 场景 | 默认做法 | 何时使用图片帧 |
| --- | --- | --- |
| 按钮按压、弹层进出、HUD 数值变化 | `transform + opacity + mask` 运行时补间 | 不使用 |
| 呼吸、漂浮、轻微弹性反馈 | 运行时位移、缩放、透明度和缓动 | 只有轮廓确实需要变化时 |
| 角色转身、布料翻动、图标变形 | 2–4 张关键姿势 + 对齐后的 sprite sheet | 需要真实轮廓变化或形变时 |
| 复杂表演动画 | 专门的骨骼/网格/人工修帧管线 | 不把大量独立 AI 图直接串联 |

UI 优先用运行时动画。图片序列只承担无法由几何补间表达的轮廓或形变。

## AI 关键姿势约束

需要图片帧时，优先在一次任务中生成一张对齐 sprite sheet，而不是逐张独立生成。所有帧必须锁定：

- 同一画布尺寸、相机、主体比例、朝向和构图；
- 同一 pivot/脚底点/视觉中心，且禁止逐帧自动裁切；
- 同一身份、服装、图形结构、调色板、光照和背景模式；
- 明确的帧顺序与每帧时长；循环动画的末帧必须能自然返回首帧；
- 透明素材必须是真实 alpha PNG/WebP，并按仓库透明度规则检查浅色、深色和高饱和背景。

如果相邻帧仍出现身份漂移、背景跳动、pivot 跳动、白边或色边，应判为失败并重做，不用调高播放速度掩盖。

## 时间与节奏

播放必须按已过去的时间计算，不能按“每次 render 前进一帧”。Web UI 使用
`requestAnimationFrame` 的时间戳或引擎时钟；sprite sequence 使用每帧时长表。30、60、120 Hz 下，
动作耗时与最终状态必须一致。

默认节奏 token：

- 按压反馈：80–120 ms；
- 微反馈/小提示：120–180 ms；
- 面板进入或退出：180–260 ms；
- 非交互环境循环：600–1600 ms。

进入用 ease-out，退出用 ease-in，轻度强调可用小幅 back-out。常规 UI 禁止线性运动；overshoot
只用于一次短促强调，且必须回到稳定状态。

## 运行时要求

- 第一次显示前预加载并解码纹理或 atlas；播放中不得切换图片 URL。
- 共享纹理和 atlas，不在动画循环中创建图片、纹理或大量临时对象。
- 交互状态与视觉状态分离；动画结算期间不能吞掉关键输入。
- 同一时刻只突出一个主要 UI 重点，避免多个元素争抢注意力。
- 支持 `prefers-reduced-motion`：改为短淡入淡出或立即到达最终状态，语义和可操作性不变。

## Builder 验收

Builder 必须为 UI 动效写聚焦测试，至少证明：

1. 30/60/120 Hz 模拟时得到相同最终状态与大致相同总时长；
2. 动画开始前所需纹理/atlas 已完成预加载；
3. `prefers-reduced-motion` 能走降级路径，功能不丢失；
4. 动画结束后 transform、opacity、焦点和可点击状态回到明确的稳定值。

人工或视觉 QA 以 0.5× 速度和循环播放检查身份稳定、pivot 稳定、背景不抖、无透明边缘光晕。
