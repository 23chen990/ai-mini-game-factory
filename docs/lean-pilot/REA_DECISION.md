# REA 接入与投入决策：先证明有用，再扩大

## 现在的结论

**按需接入，不常驻，不把每款小游戏都送去逆向。** 当前 2048/合并母版有可读、许可明确的参考源码，直接读代码更合适。FORM 的第一张满意图片、车身身份保持、局部修改和每张可用作品成本，优先靠真实使用与同题图片实验；不能靠静态分析判断效果，更不能把客户端字符串当成后端真正使用的提示词。

这次落地的是**离线接线代码和执行说明**：先判断需不需要 REA，再读取真实 REA 导出的静态 JavaScript 报告，核对来源与引用，输出不超过三项具体产品建议。不是已经安装了 REA，也不是已经证明开发速度、留存或利润提高。

详细接口、命令、环境、兼容范围与后续开发边界见 [REA_INTEGRATION.md](REA_INTEGRATION.md)。默认关闭的 [Codex 配置示例](../../examples/lean-pilot/rea-codex.toml.example) 只是普通文件，不会修改任何账号或开发配置。

## 最小工作流

| 步骤 | 实际要做什么 | 结果 |
|---|---|---|
| 普通研究 | 一项问题，先试玩、浏览器观察或直接读合法源码 | 记录已经知道什么、还不知道什么 |
| 判断是否升级 | 只有客户端结构问题仍影响实现，且材料权限清楚，才考虑 REA | 允许“不需要 REA”作为正常结论 |
| REA 外部采集 | 仅在单独批准的研究环境中，分析只读的授权目录/ASAR | 私有保存完整原始输出、版本、退出状态；不进公开 GitHub |
| 离线校验 | `inspect` 检查真实文件哈希、目标绑定、报告结构与语义校验和；`anchor` 自动算精确引用哈希 | 防止错配和模型编造字段；不把哈希当真实性证明 |
| 转为建议 | 每项写明修改前状态、操作、修改后状态、可见反馈、失败恢复、文件范围和验收场景 | 仍是待审批建议，不自动修改产品 |
| 检验价值 | 连安装准备、分析、复核和失败尝试一起计时计费，只统计新增的可行动决策 | 无增量、费用未知或超预算，就停止继续投入 |

使用者是研究开发助手，不是要求老板每天手填一堆表。老板只决定目标/预算、核心体验是否继续、以及商业试验是否继续。

## 什么叫有用，而不是漂亮报告

“发现了 100 个模块”不算成功。“找到一个客户端预览与最终提交分离的证据，因此下一轮可以验证减少无效提交的设计”才可能是有用发现。还必须继续检查实际实现效果。

建议第一轮上限：**新增有效人工时间 30 分钟、最多两次尝试、未批准的现金支出为零**。这不是本次授权花钱，也不是工具能强制中止外部 REA/模型进程的承诺。接线代码只会在计划与报告阶段判定超限；执行者必须遵守外部操作上限。REA 的单源超时参数不等于整次研究超时。

一次新增可行动发现只返回 `ONE_TRIAL_USEFUL_NOT_PROVEN`，不能宣布系统高效。连续两次同类研究没有新增有用决策，就暂停 REA。要声称更快，应比较相同问题、相近材料与操作者水平，并统计研究＋开发＋QA＋返工的总成本，避免把熟悉了题目造成的提速记在工具头上。

## 两个产品如何使用

**小游戏：** 建议经产品审核后，进入指定工作区，再由已有规则测试、正常触摸浏览器验收和真人筛选判断。静态代码中的“存在某个状态”不是“玩家能感受到这个状态”。

**FORM：** 输出固定为 `FORM_NEXT_VERSION_REVIEW_ONLY`，接入原研究室的建议评审。不改活跃 PR #3、资金/身份/删除逻辑，不改冻结 F00—F38。不要把竞品的未授权代码、照片、令牌、原始抓包、专有提示词复制到任何公开仓库。

共享来源校验、引用定位和研究成本，不共享游戏与图片生成的质量分数。REA 不负责生成策略拍板，也不替代目前 FORM 的业务独立审查。

## 本轮真实验证边界

新代码有 33 项本地自动测试，使用**明确标注的合成数据**，覆盖路由、错目标、假哈希、错误引用、原型命名属性、格式错误、来源缺失、未知费用、超预算和 FORM 隔离。独立计算的校验向量用于检查算法一致性，不是假装真实 REA 报告。远端是否通过，请看当前提交的 GitHub Actions，不能沿用旧提交结果。

当前支持的是所审查版本 `analyze_javascript_application` 的直接 JSON 导出：目录/ASAR、静态派生结果。不是整个 REA 的全部格式验证器；不支持随便把 MCP 包装、其他命令或错误对象塞进来。遇到不支持的真实格式，保留原件并做小范围兼容修复，不默默裁剪或猜测。

本轮没有安装或运行 REA，没有付费调用，没有真实竞品二进制实验；因此**实际提效、模型开发收益、可玩性和商业结果均未被证明**。已有游戏工程验收通过不能替代这些证据。

## 唯一值得推进的下一项

在明确批准独立环境/安装/目标后，先用一个自有小型 JavaScript 目录做真实接口贯通检查，再选一个普通方法确实没解决的授权客户端问题做对照。先回答“多花这些时间到底少猜了什么”，不要先扩建 Agent、自动数据库或全平台逆向系统。

下一模型：先读本文件、REA_INTEGRATION.md、PILOT_START.md 和当前 PR/CI；跑 `npm run pilot:test`。不得编造研究记录、自动装 REA、把停用配置变成启用、改 FORM 主线、降低验收阈值或宣称已经验证商业效果。只修具体失败，保留明确的未验证项。
