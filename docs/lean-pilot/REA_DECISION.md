# REA 接入决策（2026-10-12）：研究透玩法是先决条件

## 纠偏

之前的判断“先做成熟母版，REA 只是按需的小工具”**不适用于当前问题**。用户的母版一直做不好的核心原因之一，是此前的竞品研究缺少客观、可复现的玩法因果规则：常有功能，没有压力节奏、可见反馈和玩家重玩动力。

新的优先顺序是：**真正的竞品体验与机制研究 → 关键规则可复现 → 三分钟高保真竖切 → 独立体验与修正 → 才决定是否复用为母版。** REA 现在是重要的前期研究工具：对可合法分析的客户端，尽早追查状态转换、计时、数值和输入/输出规则，结合实际操作，而不是等母版写完才用。

- **完整母版研究**：按 [REA_GAMEPLAY_FIRST.md](REA_GAMEPLAY_FIRST.md) 进行；不再受旧方案 30 分钟的局部问题限制，允许花数小时把一个循环挖透，但要先证明目标可访问/许可充分、记录成本上限。
- **局部难点排查**：使用此前实现的 [REA_INTEGRATION.md](REA_INTEGRATION.md) 离线 JS/Electron 静态报告桥接；可采用约 30 分钟两次的建议上限。该工具不是浏览器/Android/原生研究的完整适配器，绝不能因此忽略这些平台。
- **FORM**：竞品客户端研究可以帮助定位可见 UI 行为与客户端参数入口，但图片是否保持车型、局部编辑是否漂移、每张满意作品的成本，必须用配对图片与真实使用验证；不能从客户端猜服务端秘密提示词。当前业务 PR 继续独立。

## REA 真正能帮助的与不能帮助的

官方提供 JavaScript/Electron 静态分析、网页的 CDP 观察/受控浏览器场景、Android APK 的 JADX 方法检查以及原生程序的分析提供者，具体依目标、合法权限、平台和安装环境而定。官方案例中可从旧游戏二进制还原某段规则并独立测试；**这支持“精确机械规则逆向有用”，不自动证明大型经营游戏整体复刻完成**。

## 接下来应当真正完成什么

首个实证必须是：**一个参考游戏的“输入—状态—可见反馈—压力—补救”全链拆解和三分钟竖切对照**。推荐以医院调度经营的一个闭环为难度验证，不同时造三种母版。对无源码、但获准分析的目标使用 REA 浏览器/Android/原生工具；对有可信源码的目标直接追函数并做行为对照。

完成证据包和可开发规格之前不要继续扩大平台架构、自动报表、Agent 职位或换皮模板数量。完成后应再次核对真正独立试玩的人能否理解忙碌并愿意再来一局。

**当前尚未完成：REA 在本项目真实目标上的运行验证；完整参考游戏录屏/行为采集；真实跨游戏母版因果链复原；真正玩家体验。不要把计划或静态源码案例冒充这些工作。**
