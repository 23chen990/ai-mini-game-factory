# 可执行工厂第一条闭环：从玩法规格到门诊试作

## 这轮交付是什么

不是再建设一套 Agent 系统。原 `tools/lean-pilot/runner.mjs` 现在通过同一个候选注册表支持原数字合并游戏和一个中文门诊调度试作。两者共用独立工作区、真实源码归档、校验、预算账本、HTTP预览、HTML导出和状态报告；分别使用各自的玩法测试与真人筛选规则。

**四类玩法的工作单已支持，不等于四类游戏已可自动生产。** 当前仅有两个明确实现的候选；新门诊仍标 CANDIDATE。`build` 是对已经写好并接受测试的一个具体代码配方进行实例化，不是把任意自然语言合同自动编译成好游戏。没有调用模型、安装 REA、修改 FORM 或实际《静岚医院》仓库，没有合并或部署。

门诊运行路径为 `runs/<run-id>/workspace/game/`。它是工厂内独立试验，不可冒充已重构原医院项目。它提供的是通用服务调度机制，不作医疗建议或真实临床模拟。

## 最短使用方式

仓库分支：`feat/profiled-gameplay-workflow-20261012`。从仓库根目录使用 Node22 或更新的受支持环境。初始化、引擎测试、预览、对照与导出不安装新包：

```sh
npm run pilot -- build my-clinic
npm run pilot -- check my-clinic
npm run pilot -- serve my-clinic
```

打开终端显示的本地网址即可玩。部署前需另做平台适配，不能把本地网址说成公开试玩站。

```sh
# 两个入口仍用同一个运行器，不另外造一个“经营工厂”
npm run pilot -- init my-puzzle observatory
npm run pilot -- check my-puzzle

# 需要仓库原有锁定 Playwright 依赖，以及已安装的 Chromium
npm run pilot -- browser my-clinic

# 不调用模型的定量机制对照
node tools/lean-pilot/clinic-balance.mjs my-clinic

# 导出独立中文HTML、看真实结果、给下一开发者边界
npm run pilot -- export my-clinic
npm run pilot -- report my-clinic
npm run pilot -- handoff my-clinic
```

不能重复 `build my-clinic` 覆盖已有进度。继续改原工作区并复测；不能靠改run-id隐瞒修复耗时。测试用临时隔离目录不属于一轮产品研发的预算重置。

## 从研究到实现如何真的接通

`examples/lean-pilot/clinic/` 保存固定公开源码摘录、来源许可说明、原始字节hash、研究清单、请求与具体合同。构建命令实际执行原四类型 `planWorkflow/auditContract`，再核对合同与 `candidate.json` 中的实现绑定；来源错配或规格变化先阻塞，不悄悄套旧实现。批准后要改变规格，必须同时复核代码与测试，不能只改hash把它放行。

通过后，运行器复制六个实际运行文件和原生测试，把请求/合同/证据冻结到独立run。原子写入账本，保留失败文件，不覆写别的游戏。旧 `factory new/run` 大编排器并未被暗中迁移，旧任务与冻结版本仍按原路径执行。

研究已真实读取 CorsixTH 固定版本 `06b42b221c8da5497f07504fd01039090ccdb3d5`：
- `CorsixTH/Lua/queue.lua`：实际等候与预计来客分开。
- `CorsixTH/Lua/rooms/gp.lua`：医生技能与一段桌面处理时间相关；不是完整治疗时间。

本游戏**没有复制其数值、UI、资产或规则实现**。4.5/8.5/5秒、价格、180秒班次和26人目标都是本轮原创设计假设。源码摘录只用于可核验的研究证据，带许可，不进入导出的游戏HTML。没有竞争产品真人录像、真实REA运行、用户喜欢或盈利证明。

## 玩家实际能做什么

病人依次抵达、挂号、走向诊室、等候、接受服务、付费离开。等候过久会离开，系统记录发生在挂号还是诊疗，不产生治疗收入。

一位机动助理在两个岗位间调动，需要三秒路程，在路上不加速任何岗位。助理只帮助一个诊疗位置，不会让所有医生同时凭空翻倍。

设备缩短基础诊疗时间。扩建产生第二诊室但不会自动产生医生；继续招聘才能增加并行接診能力。每笔投资和工资都有实际支出，资金不允许负数；简化试验中工资最多扣可用资金，不模拟债务、破产或临床安全风险。旧的服务设施继续工作，不能靠弹窗强迫消费。

同一run固定来客种子，允许公平重玩。屏幕上有队列、来客预告、服务状态、助理位置、收入、等待流失和分岗位结算。1倍/3倍节奏是玩家可见的普通操作。后台自动暂停，无离线惩罚、付费或广告。重新开班重置本次实验，并不伪装成长线存档游戏。

## 哪些反馈已经可自动比较

`clinic-balance.mjs` 对**实际复制后的引擎**执行同种子三策略：不额外干预、只支援挂号、合理投资且按瓶颈调度。报告到客/完成/流失/未完成、每个岗位的流失、总等待和收支。正确策略应有可观察收益；它不是全局最优策略证明，更不证明玩家自然会这样玩。

引擎测试另对多组种子核对患者守恒、钱的守恒、岗位容量、投资依赖、存档恢复、暂停和终局。单独的HTTP浏览器检查用真实触摸、完整班次和再开一班；存储拒绝明确标为注入式环境用例。源码模拟、脚本正常输入、真人体验三种证据分开。

**只有结构检查、引擎或浏览器通过，仍然 `publishable=false`。** 不是足够好的商业母版。门诊不再误用数字合并游戏的“首次合并”真人指标；默认真人为NOT_RUN，经独立实际记录后才考虑有限样本筛选。

## 给下一位较弱Codex的文件边界

- 类型→具体实现：`tools/lean-pilot/candidates.mjs`。未知候选必须报错，不回退到另一种游戏。
- 规格→实例：`build-workflow.mjs`。只支持注册的固定假设；不添加任意shell、网络或收费能力。
- 共用执行：`runner.mjs`。保持旧合并游戏回归；不要复制一个新运行器。
- 游戏规则：目标run内 `workspace/game/engine.mjs`；界面与动效：`main.mjs / style.css / index.html`。
- 原生策略对照：`tests/engine.test.mjs` 与 `clinic-balance.mjs`；浏览器正常流程：`clinic-browser-qa.mjs`。
- 冻结证据与验收不允许由Builder为过关而修改。确需新设计，先有范围明确的新合同与回归，不通过清空账本、改测试或假记录绕过。

下一项应改真实试玩暴露的断点，例如玩家看不出要先开房再雇医生、助理切换过勤、某个投资始终不值得。不要顺手加排行榜、抽奖、五种新病人或另一个Agent框架。

## 本轮验证口径

本地实际运行了引擎与构建/证据测试，并用自有独立HTML做了三个尺寸的离线DOM截图检查。此环境的HTTP导航返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，所以不把离线截图当真实HTTP验收。远端CI会在同一次工作流内保留原合并游戏验证，再构建、测试、模拟对照、浏览器实玩、导出门诊。最终是否通过，以PR最新提交的实际日志为准。

仍需：真实目标手机、未经指导的玩家、长期体验、发布平台包、获客和收入验证。REA分析闭源目标仍需明确许可与独立环境；此实现不安装REA，不用假Evidence代替真实运行。
