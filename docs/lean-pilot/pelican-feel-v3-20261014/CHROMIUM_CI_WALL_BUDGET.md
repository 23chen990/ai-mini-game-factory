# Chromium H5 CI 单关墙钟误报修复

## 发现
GitHub run 38538939725 的 WebKit 已自然触屏完成五关，以及首关跳跃获得奖励金鱼、三星、正常绕路、重开和存档。
同一提交的 Chromium 在第2关 388/420m 处达到 `qa.mjs` 单关固定 135 秒墙钟上限：`reason=null`、`phase=running`、`elapsed=48.5s`，不是撞车或跳跃失败。该 runner 使用软件 WebGL，进度慢于实体设备。

## 修改与边界
- 新增 QA 专用 `runtime/qa-budget.mjs`：单关墙钟预算以固定关卡距离/速度推导，约为正常骑行时间3.5倍，限制135-300秒。不改变游戏主循环 `dt`、角色速度、撞车、抓鱼、星级和玩家触摸操作。
- QA 日志新增 `driveBudgets[]`：记录每次驱动的墙钟时间、游戏内时间、距离、`status` 和失败原因。超预算时仍 FAIL，保留现场截图和可复查信息，绝不硬标绿。
- Pelican 专属浏览器 CI 单 job 上限从20到25分钟，避免耗时环境在正常通关前提前杀掉任务。
- 新增纯规则测试检查预算分级、上下界和显式覆盖，不接受 NaN/非法值。

**本修复不代表实体手机性能已合格。** Codex 仍须在真实 GPU 的 iPhone/安卓上验证30/60fps 手感、长时间热量、后台恢复和广告；若新 CI 仍失败，保留真实失败证据，不准通过跳关或快进作弊。
