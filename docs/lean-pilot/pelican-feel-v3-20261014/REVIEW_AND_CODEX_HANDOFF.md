# 《鹈鹕海岸冒险》V3：骑行手感、镜头与五关公平性修复交接

> 基线：`23chen990/ai-mini-game-factory` 的 PR #13，commit `600d529d565e238bbc23432e6726dd84a77dda2f`。本次从该提交另开独立 Draft PR，不合并，不部署，也不改 PR #10/#13。本文与代码提交互相对应；本次不是生产发布。

## 1. 本轮修复（已提交代码，待实际 H5 复测）

1. **恢复转向惯性**：`runtime/feel.mjs` 使用对帧率不敏感的临界阻尼解析式，保留 3 车道“一次输入移动一格”的简单规则；将横向速度、加速度传给车头、车身倾斜及偏航，不再把整辆自行车瞬移/整体平移。
2. **恢复活的追踪镜头**：镜头目标使用实际横向位移、小幅速度预判及跳跃高度，位置与注视点分别缓动；视角从旧 V2 的竖屏 54° 调到默认约 52°，高度稍低、主体稍近。采用稳定追拍而非恢复原版 orbit/cine 自动旋转，避免晕动和看不见障碍。数值仍需真机看画面后细调。
3. **统一时钟**：`build.mjs` 中 `coast.beforeRide(timer.getDelta())` 改为 `coast.beforeRide(dt)`，避免帧更新和物理逻辑在长帧/后台切换时不同步。
4. **行人安全**：`runtime/safety.mjs` 复用相同的预计过街位置公式给关卡鱼道配置和 HUD 雷达。原版 V2 将“左边走来的行人”错误地判为“最右车道安全”；现在预测未来接触位置，约 4 秒前提示危险车道。提示须在真实移动录像里复核，不是仅验证数学。
5. **移动端手势**：保留三颗可见按钮，同时支持直接在 3D 场景中左右滑动变道/上滑跳跃；不增加新 UI 按钮。
6. **五关目标与星级**：鱼目标由 `6/9/12/15/18` 调至 `8/12/17/20/24`，第 3、5 关金鱼目标增加；第 4、5 关时间上限适度收紧到 88/95 秒。1 星=达标通关；2/3 星要求额外捕鱼与无碰撞，高星还要求额外金鱼、合理时间。降低“随便跑也满星”的问题，保留容错。
7. **反馈**：成功跳过路障给简短提示；结算说明如何冲三星；前方有行人时雷达给出明确的横穿提示。

## 4. Codex 一次性收尾执行顺序（请按顺序执行，不要把真机未过宣称为通过）

1. 读取本 PR 代码、PR #13，以及 `tools/lean-pilot/pelican-v2/README.md`、固定原作者 SHA。只操作这个独立工作区，不重新搭建工厂，不碰赛车/医院/恋爱游戏和任何其他 PR。
2. 首先运行 `node --test tools/lean-pilot/pelican-v2/core.node.mjs tools/lean-pilot/pelican-v2/runtime/feel-safety.node.mjs`，`pnpm exec eslint tools/lean-pilot/pelican-v2`，`pnpm exec tsc --noEmit`（根据仓库有效脚本调整，但日志要留存）。发现失败应正常修源码/测试，不要通过跳过测试过关。
3. 使用现有 `prepare`/`build`（严格遵守源码 pin、attempt 机制）。如果上一轮 workspace 已有旧构建，应从**相同 immutable source preimage**重新构建新代码；切勿复用 PR #13 的旧 HTML 和旧 buildHash 当成果。
4. 桌面 WebKit 与 Chromium 用实际触摸事件自然跑完五关（重新建立存档，从第一关通关解锁下一关，不写 `__coast` 状态），核对捕鱼和金鱼、雷达行人左右预测、雨夜能见度、失败重玩、暂停恢复、广告未接入不可发奖。
5. **重点做手感 A/B**：同机位、同方向输入录 PR #10、PR #13、V3，对比车头先转-车身倾斜-平滑转向-回正以及动态追拍；测试一次右滑、左右连点、反向急转、跳跃并变道、撞人后恢复。录屏含输入时间，不能只给截图或“17 项感知通过”一句话。
6. 至少检查 390×844、360×740、320×568 竖屏和 844×390 横屏；按钮触控不遮挡障碍，游戏画面始终有道路、主角和行进前方；实际低帧/弱机优先降特效，不要把分辨率拉得过低。
7. 第 1 关 x≈90 左侧来行人，应事先把**右道**显示风险；从右侧来的行人相反。捕鱼指引不能和危险雷达相冲突。正常通关策略与故意撞人策略要分开测试，防止新增提示让所有事故无法重现。
8. 真机 iPhone + 安卓中低端：实测首屏 3 秒内是否可见和可操作、帧时 P95、发热/长局稳定性；切后台、来电、锁屏、WebGL context lost 后应暂停并可恢复。没有设备就如实 `BLOCKED`，不准伪造。
9. 完成新的源码版 H5 ZIP、截图和视频、哈希、明确的 QA 报告、复现步骤；若发现视角不舒服可以对 `feel.mjs` 参数微调，但每次更改都须复测物理公平性。小步调参只改参数，不新造引擎。
10. 保持 Draft、不要合并旧 PR/新 PR、不部署生产、不假装广告已接入。提交一个清晰完整的最终交接，包括未完成及下一步用户只需验收的 2-3 个问题。

## 5. V3 质量门槛

- 手感：第一帧移动须明显小于整个车道；普通变道约 0.25–0.4 秒进入目标道；车身偏航不出现突然 60°+ 的扭转；连续反向点击时位移速度连续。
- 公平：所有关卡给定合法操作可通关，真实 HUD 警告至少提前约 2 秒，预判行人与实际碰撞落点一致；金鱼不能故意摆在唯一致死路径上。
- 可读：3D 主角、三车道、前方障碍在标准竖屏一眼可见。镜头微弱滞后即可，不自动环绕、不猛烈晃、不晕动；画质不应牺牲操作反馈。
- 生命周期：第一分钟应获得一次明确的鱼反馈、一次清晰避障决策、进度提升和合理的通关/奖励目标。通关后能理解如何冲三星，满星应成为后续挑战目标。
- 工程：新提交物理单测 / 集成浏览器测 / 质量门槛都过，真实广告与真机不达标就不宣称生产放行。

## 6. 已知边界

这个 PR 修复的是具体可验证的工程与初步数值平衡。玩家“觉得更自然、更愿意多玩”依然需要对比录屏和真人验证，不能用 Node 单测替代。后续若玩法依然短，优先调整每关高星挑战、鱼的分布和障碍节奏，不要贸然引入重型排行榜/新后端/复杂 NPC 系统。
