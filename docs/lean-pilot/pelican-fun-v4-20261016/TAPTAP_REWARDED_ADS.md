# TapTap 自愿广告复活接入准备（2026-10-16 核对）

游戏：鹈鹕海岸冒险。工作区：`runs/pelican-coast-v2-20261014/workspace`。本 PR 为 H5 开发试玩；广告保持 `NOT_INTEGRATED`，不申请开通、不创建广告位、不上传或发布包。

## 官方已确认的接入条件

- 按 [官方广告接入指南](https://developer.taptap.cn/minigameapidoc/quick-start/mcp-guide/ad-integration-guide/) 完成开发者认证、财务主体和收款资料，在对应游戏的「商店 → 小游戏广告」申请开通。该页将这条变现流程的适用范围限定为星火、H5 小游戏和 TapTap 制造；普通 Tap 小游戏/APK 的广告路线需要另行确认，不能拿 H5 证明原生平台已接入。
- 按 [官方广告概览](https://developer.taptap.cn/minigameapidoc/dev/tutorial/open-capabilities/ad/ad/) 取得真实广告单元 ID、接入目标平台 SDK/API 并测试。广告位 ID 和获批状态均未在本次工作中取得。
- [激励视频官方说明](https://developer.taptap.cn/minigameapidoc/dev/tutorial/open-capabilities/ad/rewarded-video-ad/) 要求由用户选择观看；`show()` 成功只表示展示。仅 `onClose` 的 `isEnded === true` 可作为完整观看信号。取消、缺少结果、错误和超时不发放权益。
- [RewardedVideoAd API](https://developer.taptap.cn/minigameapidoc/dev/api/ad/RewardedVideoAd/) 描述了 load/show 和监听清理。组件是单例；复活与结算补给共用宿主能力时必须串行，移除本次监听，不能把同一个关闭事件计为两种权益。

## 本项目需要的配置与权益隔离

| 项目 | 当前状态 | 启用前必须留存 |
| --- | --- | --- |
| 目标宿主/SDK 版本/游戏身份 | 未验证 | 实际目标 H5 宿主、SDK 文档及版本、正确游戏身份 |
| 开通与广告配置 | PENDING / NOT_RUN | 真实获批状态、真实 appId、对应 adUnitId；不能只改 status |
| 复活广告位 | 未创建 | 单独用途 `revive-once`，每局最多一次；不与额外补给混用 |
| 结算额外补给位 | 未接入 | 独立权益绑定、既有频率限制和一次领取约束 |
| 官方完整观看证据 | NOT_RUN | 真实关闭回调、时间、目标局/广告请求/权益类型及去重记录 |
| 微信/抖音/Tap 原生包 | NOT_PACKAGED | 各自适配器、配置、官方平台运行与包体验收 |

仓库现有 H5 适配器要求 `status === 1`、`source === 'check_ads_status'`、appId、非空 spaceId（传给 adUnitId）、横屏配置值和真实 `tap.createRewardedVideoAd`。这些是本仓库已有的安全门槛，不能把字段名当作已核验的公共平台配置接口。PR19 使用冻结的 PENDING 配置，不接受 URL 参数或本地存档启用广告。不得硬编码密钥；后续接入的秘密信息只从环境变量读取。

## 应验证的完整权益流程

1. 在真实碰撞死亡时停止模拟。配置缺失则立即结算一次，显示广告复活不可用，并保留免费重开；不向 SDK 发出请求。
2. 配置与 API 已真实验证后，只有尚未结算的首次车辆/路障死亡可等待自愿复活；超时、缺鱼、缺金鱼和已复活的死亡不提供第二次复活。
3. 用户点复活后绑定当前局对象、请求代次与 `revive-once` 权益，串行调用官方适配器。不得按 load/show 成功、Promise resolve 或本地计时器判定观看完成。
4. 只接受官方完整观看结果。发放前再次校验当前局、请求代次、未结算状态和剩余次数。重复回调、跨局晚回调、已结算或已经离开的请求全部失效。
5. 消耗一次复活、清除造成死亡的障碍、归零空中/残留转向，先停在可见「继续」界面。玩家继续后才消耗 2.5 秒保护。保护期间不凭无敌擦车刷分；一次失败后的无碰撞三星不能被恢复。
6. 取消/错误/超时保留复活次数，允许重试或免费重开。重开或选关会作废请求并将待结算终局结算一次。下一次死亡或最终通关只结算一次；原有额外补给也只允许领取一次。

官方已查文档提供的是客户端 `isEnded` 判断，未在这些来源找到可直接采用的「激励广告服务端验签/回调地址/签名算法」。不捏造 API、密钥或服务端验证已经完成。若最终宿主/广告联盟提供服务端验证，须取得该产品的官方合同再实现请求绑定、签名校验、防重放和一次发放；当前不引入后端。
