# 逆向研究驱动小游戏工厂：可执行增量与 Codex 交接（2026-10-13）

## 快速结论

当前代码在独立研究分支上，**不是**已经打通 REA 的全自动生产线，也不是发行认证。保留原主编排、原游戏和其它 PR 不动。这一轮只新增一条可执行的**源证据 → 玩法机制 → QA 对照 → 原创竖切开发**交接门禁：`tools/lean-pilot/research-to-build.mjs`。

本分支**以 PR #3 的 head 为父分支**（该分支依赖 PR #2），PR 评审和合并不得跳过依赖链。旧的 REA 桥继续只处理已授权 JS/Electron 静态导出。新增研究门禁不运行 REA，不运行竞品代码，不验证实际游戏乐趣，不修改游戏样片，不证明源码许可证授权覆盖所有素材。

## 运行

在含有 PR #2 + PR #3 文件的完整仓库根目录，Node 22.16.0 及以上，零额外依赖：

```sh
node --test tools/lean-pilot/tests/research-to-build.test.mjs
node tools/lean-pilot/research-gate-cli.mjs examples/lean-pilot/clinic research-to-build.json
npm run pilot:test
```

第一条要通过所有正反测试。第二条输出 JSON 的 `status` 应为 `SOURCE_BOUND_PROTOTYPE_HYPOTHESIS`，`candidateBuildAllowed=true`，但 `releaseAllowed=false`、`referenceRuntimeObserved=false`、`reaExecutedVerified=false`、`humanFunValidated=false`。任何 `BLOCKED` 状态必须停止制作母版。**只有研究身份、文件和证据一致、来源到机制/验收可追溯，才允许进入候选竖切开发。**

`examples/lean-pilot/clinic/research-to-build.json` 是真实 CorsixTH 固定版本**源码引用** + 我方设计假设的示例，不是运行过 REA。原例 `research.json`、`request.json`、`contract.json`、`reference/` 保持原样。三场景输入仅是将来浏览器对照的脚本契约，**尚未作为自动试玩执行**。

## 证据和产线边界

- 参考研究前先挑一款主参考及最多两款辅参考，先确认获取与研究许可。优先公开许可源码、自有游戏或明确授权可分析程序。
- 读取现有 `docs/lean-pilot/REA_GAMEPLAY_FIRST.md`、`HOSPITAL_SOURCE_MECHANICS_CASE.md`、`REA_INTEGRATION.md`。不要回退为竞品功能清单；必须找到状态转移、事件时机、数值变化、失败恢复和肉眼可见的反馈链。
- 先从直接源码或真实操作拿到有效证据。已知源码可读时，不能为了使用 REA 而增加成本。REE/R​​EA 安装、分析特定商用闭源包之前分别检查适用授权及工具支持；本轮未批准绕过访问限制。
- 机制引用必须来自 `SOURCE_CODE` 或 `OBSERVATION` 类型证据，并在 `requiredClaimIds` 内；所有被列为必需的机制都要被映射到一条原创设计循环和可执行 QA case。推断、教程、宣称、UNKNOWN 不能充作硬证据。
- 相同种子/初态/输入窗口下，必须有“不操作／只操作一次／主动调度”三个对照，且标明**用可见正常输入**、不靠 debug/state injection。玩法实现后需要补入真人可观察的输出指标和可重放录像，不能仅靠此 JSON 预测胜负。
- 参考的第三方代码片段、可识别画面、美术、文案、关卡、二进制只留经过许可的私有研究目录和必要说明，不要上传公开仓库。按许可证分别处理代码和素材；现有案例采取规则启发、原创实现，未移植参考代码。
- 散列值证明研究文件是否被替换，不证明实际许可、报告真实性、REA 真实运行或真人试玩来源。任何无法证明的事实写 `UNKNOWN`，不能反向填 PASS。
- 完整研究与单点排障两种任务分开预算；不要把旧桥“30 分钟研究单点难题”限制用到整个母版探索。
- 用户最终只需要简体中文手机试玩链接或单 HTML、简短验收页面、问题和下一步建议；英语技术日志保留给开发。

## Codex 必须完成的工作（不要以再写一份报告代替）

### P0 — 跑通本分支并修正真实缺陷

1. 从 PR #2 → PR #3 的依赖链确定合并策略（只建议、不擅自合并），先在本 PR 分支跑 `node --test tools/lean-pilot/tests/research-to-build.test.mjs`、`npm run pilot:test`、浏览器测试。指出**实际**失败用例，不要把测试代码改成永远通过。
2. 检查节点适配和前端三种场景的可执行性。现在 `counterfactual.actions` 仅是**自然输入脚本**，Codex 要根据前端真实 DOM/场景命中区域接入 Playwright/触屏回放，并验证可点击性、画面和真实状态一致。所有截屏/录像绑定 buildHash、版本、固定种子。
3. 用数据表和可见画面比较不操作、单次操作、主动调度：排队、患者流失、服务完成、可用资金、压力出现时间、补救响应时间。显示差异不等于好玩，但差异不成立就必须 FAIL。
4. 独立 QA 复核无法解释的差异、假阳性、UI 操作过密、移动端横竖屏、刷新存档、广告入口边界。QA 不得自行修改测试口径或提供虚构的真人会话。

### P1 — 真实 REA 烟雾测试 + 独立研究

5. 在**独立、已批准的隔离研究环境**中核对 REA 版本、Node/接口、工具兼容与许可；先研究一个自己拥有的最小 JS 程序，实际记录 `rea analyze-javascript-application --help`、版本、退出码、输出、哈希、耗时，验证 `rea-cli.mjs` 的 `plan/inspect/anchor/review` 全流程。不允许把合成 `rea-bridge.test.mjs` 输出称为 REA 实际运行。任何真实包不符合授权或不能取得，停止并报告原因。
6. 只在确有必要且授权明确时选择一个合法闭源/构建后客户端，具体追踪至少一条状态触发函数和关联 UI 反馈；结合真实操作核对，不允许仅凭静态调用图推断整个游戏体验。针对 web/Android/原生目标先验证该 REA 版本的实际可用操作；已有桥**只接受 JS 静态导出**，不要假装它能直接分析 APK。
7. 通过人工审查将 REA 派生结论纳入证据、候选设计和独立 QA：添加明确的 `REA_STATIC_DERIVED` 证据类型与真实导出绑定，明确归类为**派生推论**，不能直接提高成源运行时观察；更新 CLI/tests 并保留旧报告的兼容性或迁移测试。旧桥 `reviewExport` 的校验记录不是公钥签名，不证明真实包运行成功。

### P2 — 工厂整体收口与长期成本

8. 统一 PR #2、#3、#4、#5 的冲突与重复功能，尤其两个不同的外部游戏复审入口；独立核查之前的预览超时和全回归失败，不修改其它 PR 的业务范围。
9. 统一 AGENTS.md、README.md 和实施计划里自动 Fixer 修复次数的冲突：以**可追溯且有预算的修复策略**为单一来源，区分无解停止、升级策划问题、允许继续及实际成本上限。
10. 生产线只维护一个共同控制层，经营、跑酷、剧情、益智按不同体验类型验收；不要为每种玩法复制一个完整 Agent 工厂。仅当真实竖切能通过重放、触屏、人工审查后才能把它认证为复用母版。
11. 每个可交付游戏提供中文验收 HTML、原生输入测试结果、参考差异、失败项、来源许可复查表、实际成本和 `GO / FIX / STOP` 判断；本轮**不合并、不部署、不投放、不提交第三方原始二进制/密钥**。

## 验收纪律

| 范围 | 允许标 PASS 的真实条件 | 未满足时 |
|---|---|---|
| 研究门禁 | 正反测试通过、证据文件可核验、机制可定位、CLI 接口实际运行 | BLOCKED |
| REA 接入 | 已获许可的自有 JS 应用实际运行工具并拿到真实输出，完整版本/散列/退出码记录 | REA_NOT_RUN |
| 玩法因果 | 三策略固定输入回放在玩家可见指标上产生合理差异，前 30 秒和 3 分钟有独立记录 | NEEDS_GAMEPLAY_REWORK |
| 可用性 | 真实手机或受控等效触摸设备，默认一倍速可操作且 UI 不挡操作 | MOBILE_NOT_VERIFIED |
| 好玩 | 独立真人试玩，不诱导，不靠 AI 模拟填写；参与者理解、是否主动继续的原始证据 | HUMAN_NOT_RUN |
| 发行 | 目标平台 SDK、IAA、自愿广告奖励、版权与许可证、隐私和故障恢复实测 | RELEASE_BLOCKED |

研究门禁允许开始**原创候选开发**，从未允许直接发行或声明“高保真复刻”。报告先显示缺口，缺口未解决就停止或回到研究，不通过造测试、改规则或漂亮说明书掩盖失败。
