# 审查已有游戏：外部工厂 QA 入口

## 为什么增加

工厂此前主要处理本身创建的 run。对于一个已经存在的 GitHub 游戏（例如夜市飞侠），不能通过“复制成新模板”再跑测试：那会丢失实际入口、存档和已有美术。

新增命令：

```sh
pnpm factory audit-external ./audit-input/night-market-manifest.json --output ./audit-output/night-market-report.json
```

`manifest.json` 明确目标游戏、源码提交、实际工作区、独立 HTML SHA-256，以及逐一绑定**对象×状态分支×渲染路径×视口**的用例和证据。证据种类分别为 `engineering`、`natural-input`、`perceptual`、`human-playtest`、`phone-performance`、`platform-package`。每条证据包含类型、当前构建哈希、独立审查人、输入方式、实际观察、文件及其 SHA-256。

适用于《夜市飞侠》的必测用例建议包括：普通楼檐接缝的连续镜头采样、街区跨段飞行时的背景变化、速度突变与镜头连续性、官兵距离曲线及**正常输入能触发的 caught**、首次实际看到/接触/错过载具、坠落与奖励恢复、四种载具与菜单的手机横屏检查。需填充每条自然轨迹和视觉证据，不能用另一状态或另一视口的截图覆盖。

## 安全与验收边界

1. 工具不会 checkout 外部地址、执行陌生仓库命令、修改外部游戏，也不自动生成 PASS。
2. 工具只验证本地已存在证据的 SHA-256、完整性、覆盖率、方法和审查者声明；证据路径必须留在真实工作区，不能是符号链接或 `../`。
3. `PASS` 需要所有声明的对象用例按类型通过，七个质量维度均有证据；缺任意维度、构建哈希变化、自然输入轨迹缺失、非独立感知审查或缺真人试玩，都使结果失败或 UNKNOWN。
4. 提交的“独立感知通过”声明不能替代人观看视频，更不能代替实机帧率；本工具不能从若干静态 PNG 推断运动连续。流水线必须先跑 Playwright、人工/独立感知审查，然后本命令封存已核验工件。
5. 若范围为 `commercial`，还须单独进行微信、抖音、TapTap 真实构建、包体、广告与上架工具验证。`web-lite` 的可玩证据不得冒充平台可发布。

**本工具解决的是证据串号、兄弟分支顶替、构建身份错配和漏报的结构问题，不是自动替人判定“好不好玩”。**
