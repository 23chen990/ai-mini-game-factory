# 互动恋爱剧情编辑｜先写活人，再去模板腔

## 前置约束

- 先核对目标游戏、源码工作区、正式文本和版本/提交哈希，区分正式正文、旧稿、演示稿、用户截图、测试导出。不得以记忆中的剧情补齐未确认的设定。
- 保留人物年龄、设定、时间、事件次序、已知信息来源、独立行动、本人意愿与明确拒绝。原著记忆是待验证线索，不是穿书后全知权限。人物救场不等于自动获得爱情。
- 无明确代码修改授权时，只生成审校意见和候选稿；有授权才修改正式结构化文本。先隔离新分支/工作区，不覆盖 `main`、旧版本或存档。内容变更不自动推送、发布或上架。
- 对于游戏内主循环问题，复用已有 `gameplay-loop-review`；自然游玩 QA 交给 `game-playtest`；不要取代现有工厂编排。只在剧情/恋爱选择类项目中启用本 Skill。
- 此 Skill 提炼了自然中文、去套话、人物文风锁定等写作方法，但不调用也不复制第三方“去 AI 味”Skill。禁止声称检测器能识别 AI 作者。

## 五关执行，不许顺序倒置

1. **剧情因果关**：阅读设定、当前场景的可达前缀、具体关系状态和人物证据。填写“谁看到/听到/做过什么”，与原著知识、当局现实、猜测、谣言分开；检查道具是否实际出现、时间是否连续、陆景行等非玩家角色是否能独立行动。缺铺垫时优先修剧情结构，不用台词润色掩盖。
2. **角色与关系关**：从已发表正文和角色档案提炼**行为**差异，而非给每个人套口头禅。对每句目标台词标记动机、情绪、想遮掩什么、相对于上次接触的变化。区分关注、好感、信任、约会邀请、明确同意、承诺、冲突、修复、分手、朋友。四人线都要允许慢热、拒绝、维持朋友。
3. **中文自然关**：去翻译腔、万能夸奖、抽象道理、主语不明、机械对仗、重复解释；用可见动作、具体话题、短句、插话、欲言又止替代。允许人物故意隐瞒、文艺、正式或笨拙——须有角色或剧情依据。不要把“说人话”理解成所有人都贫嘴。使用 [editorial-rubric.md](references/editorial-rubric.md)。
4. **玩家选择关**：检查“玩家看得懂选项→执行具体行为→马上看到反应→后续人物记得→不同路线付出不同代价”。确认首 30 秒悬念/操作、3–5 分钟回报、10–20 分钟关系变化（均仅为设计目标，不是自动阅读计时或留存证明）。避免强制多线、承诺回避后自动复合。
5. **结构与运行关**：正式 JSON 走“只改显示文字”的机器检查；如果要修改条件、效果、结局或状态，另立**玩法逻辑变更**工单及更广泛回归，不得绕过保护器。运行原解释器普通选择、后续回声、存档/回退、宽窄手机布局，并分开记录工程验证、作者审校、独立玩家和真实平台结论。

## 编辑方法与最低交付

- 先用 [workflow.md](references/workflow.md) 建立目标场景清单与反例矩阵，再按 [voice-bible.md](references/voice-bible.md) 建人物声线档案。针对《攻略美少女》先读 [gonglue-r4.md](references/gonglue-r4.md)，以实际正式 JSON 优先于本 Skill 的案例说明。
- 输出每个修改的 `scene_id / line_id / speaker / 触发前缀 / 原句 / 新句 / 修改依据 / 后续回声 / 是否改变语义 / QA状态`，同样记录有意保留的有个性表达。严禁“一键全局改写”覆盖条件块。
- Python 标准库保护器 [story_guard.py](scripts/story_guard.py) 只识别审查过的 `STORY.json`、`BONUS.json`、`CODA.json`、`EPILOGUES.json` 行结构。仅允许 title/body/block/reply/choice-label 展示文字，衍生 `textHash` 自动重算；其余字节所代表的 JSON 结构不能变。源哈希错、占位符改变、未知 schema、隐藏字段改变均须失败。保护器是结构检查，不是文学评分。
- 用 `python scripts/story_guard.py inventory --source PATH --report report.json` 得出版本绑定的定位线索。人工核对每条 `text` 的 `speaker`、`lineId` 并制定 `edits` 补丁（格式见 [factory-integration.md](references/factory-integration.md)）后用 `apply --source OLD --patch patch.json --output NEW --report check.json` 创建**新候选**。可用 `check --before OLD --after NEW` 对比；输出已存在会拒绝覆盖。命令从本 Skill 文件夹执行。
- 对 r4 用 [replay_pilot.mjs](scripts/replay_pilot.mjs) 在已有见证上执行普通命令：`node scripts/replay_pilot.mjs R4_ROOT CANDIDATE_STORY.json report.json`。脚本要求旧见证 SHA 与正式旧版一致，不接管真实浏览器。其他项目必须提供自己的真实引擎适配与可达路径，禁止用 r4 固定见证充数。
- 符合交付时给**完整候选正式 JSON**、差异清单、每条疑点的处理方式、工程回归原始日志、无法完成的独立体验/平台门禁。版本基线哈希缺失不能宣称通过。

## 硬性退回条件

- 文本透露角色没获得的知识，或先恋爱后同意；违反明确拒绝/承诺；角色被迫降智；选项效果被隐藏地改动；非文字字段变化；使用陈旧的回放；只做了词语扫描却报称真人满意；一次试玩未到结局却报通关；把在结构中存在当作屏幕上真的出现。
- 出现以上情况，保留失败、定位具体场景和可复现路径，修复后重跑相关与相邻路线；不要降低验收标准。
