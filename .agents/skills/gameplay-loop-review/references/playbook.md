# 实际执行手册

## 顺序与停止

先用一份工作单限定受众、平台、预算与首个渠道。再在一个主参考中追一个核心循环，不同时维护四个游戏原型。

0—30秒是观察窗口，不是强制每种游戏30秒选一次。剧情先让玩家理解角色处境；动作先体验有响应的操作；经营先看到一个可干预的瓶颈；解谜先发现可学规则。30—180秒寻找可见改善和下一次意图。时间只是试验设计，不是已观测事实。

先做一次医院“固定输入下调度前后”的小片段，可直接使用已有游戏工作区，而非另起完整医院。接着验证剧情类型是否能用同一工作单结构交出分支信息/后果规格。第二类型用于检验方法可泛化，不要求四个母版同时完成。合并游戏只作现有工程回归，不证明经营或剧情已认证。

一轮最多处理三个问题。预算明确而非默许无限修复；上限是事先决定的工程时间/费用，不按工具调用数奖励。完整新母版研究不能照搬局部REA问题的30分钟限额。模型选择按总体返工成本，不按“多Agent看起来更严谨”。

## REA放在哪儿

研究方法由证据问题决定，可在研究早期使用。已授权网页观察/脚本、可读源码、合法包分析与实际操作互证。当前仓库的REA离线桥只支持部分JS/Electron静态格式，不是完整网页/Android/iOS工具，也不是已经安装了REA。不要为陌生格式猜输出或绕过付费、权限、完整性限制。

每个结论区别：亲自操作观察、源码派生、创作者帖子声称、设计假设、未知。REA可以帮助找状态、公式和调用；不能从静态代码断言玩家喜欢、隐藏服务端提示词或利润。首个互通测试应有真实工具版本/退出状态；合成JSON不是互通证明。

## 五种驱动力如何用于发现问题

即时反馈要让玩家明白自己的操作影响了什么，不只加粒子。
变化不等于随机发奖；同一技巧可以解决新问题才是有效变化。
接近目标要有真实可达路径，不造假差一点。
积累可以是建筑、关系、知识或完整章节，不必每款都有永久装备。
离开代价只能解释停留行为，不能作为喜欢的证据；允许安心退出和可靠续玩。

“为了奖励不算”应理解为继续追问奖励的用途，不能错误排除收藏、审美和单纯获得资源的乐趣。效率+20%也可能明显改善当前瓶颈；不是每次升级都必须加一个系统。识别同一玩法是否已经耗尽，而非机械禁止数值成长。

## 循环怎样才算连起来

反例：诊疗获得金币→金币买花盆→花盆没有可见效果。不能只补签到掩盖断点。
候选修法：玩家投资等候区→指定等待行为改变→同一来客输入下流失/满意度与现金出现差异。每个因果边都需真实实现；这个例子是原创假设，不是医学模拟证据。

剧情允许分支回到共同章节；需要明确之前选择是否影响关系、信息或表达。不要要求指数膨胀的分支树。完整单局也可以给玩家“这次玩得值得”的结尾，不强迫日常回访。

## 低成本验证

工程层测状态、时序、存档和重试；自动浏览器测正常操作与可见后果；少量真人检验是否理解、主动继续和事后评价。真人测试不可由AI造记录；小样本是筛选不是留存率估计。

保留同一条件下的正反场景。动作固定局面与不同输入；经营固定来客与不同策略；剧情固定已知信息与不同选择；解谜固定规则与有效/无效推理。随机游戏要用多种种子/分布，不把“脚本某一次输了”当成必然缺陷。

上线后按同一平台、版本、渠道、新用户队列计算曝光→详情→启动→首次价值→重玩→回访→净收入。退出/后台事件可能缺失，分母和去重口径要记录。没有数据时标未知，不预建数据库；优先使用发行平台现有报表。广告自愿、奖励兑现和存档可靠另验，不以强留在线时间作为优化目标。
